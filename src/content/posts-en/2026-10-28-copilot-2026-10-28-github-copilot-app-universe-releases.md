The GitHub Copilot app now supports Projects, a single home for work that spans several repositories or doesn't touch a repository at all, and computer use, which lets Copilot operate desktop apps. Both are in public preview.

## Details

- **Projects:** Start a project, describe the goal, and add context such as repositories, design mocks, Slack threads, or meeting notes. Choose models and tools; Copilot runs as many agents as needed in the background and returns results such as pull requests for review. Project automations handle repeatable tasks, for example creating a promo video whenever a feature lands. Single-repository sessions still work as before.
- **Connected tools:** Context from tools such as Slack and Figma can be used to research a request, draft a specification, or work through a design alongside code. Images can be generated and edited in chat.
- **Computer use (macOS and Windows):** Copilot can read app content, click controls, enter or edit text, and navigate across apps, including those without an API, CLI, or MCP integration. Example given: an expense-report workflow.
- **Controls:** Copilot asks approval before controlling an app, and organizations can disable the feature through managed settings. Enable it under Settings > Computer Use; on macOS, grant Accessibility and Screen Recording permissions.
- **Plans and pricing for these features:** Undisclosed in the announcement.

## What happened next

Projects moves the app from per-repository sessions toward goal-level orchestration, matching the shared-automation and agentic features announced the same week. Computer use extends reach to software with no integration surface, but at the cost of a broad permission model; the approval prompt and managed-settings switch are the main safeguards GitHub names. Both features are previews, so behavior and availability may change.
